# GENESIS banking UAT stack on Azure Container Apps

Workflow: `.github/workflows/uat-stack.yml` · script: `genesis-banking-uat/azure/deploy-uat.sh`

Test-only environment. No live settlement, SWIFT connectivity, card issuing or real customer data.

## What runs where (resource group `genesis-banking-rg`)

| Component | Container App / resource | Ingress |
|---|---|---|
| Apache Fineract 1.15.0 (built from the official source tag) | `genesis-fineract-uat` | internal only |
| Mifos X web app (`openmf/web-app` 1.14, pinned by digest) + same-origin proxy to Fineract | `genesis-mifos-uat` | public HTTPS, Fineract sign-in |
| ISO 20022 syntax-check gateway | `genesis-iso-sandbox-uat` | internal only |
| PostgreSQL Flexible Server (Burstable B1ms) for the Fineract tenant | `genesis-fineract-uat-24a900e4` | Azure services only, TLS required |
| Fineract database migrations (`liquibase-only` profile) | Container Apps job `genesis-fineract-migrate` | no ingress; runs once per deployment |
| Images | registry `genesisbankingacr` | — |

## When it runs

- Pull requests: builds all three images and smoke-tests the gateway and web-app proxy. No Azure access.
- Push to `main` touching `genesis-banking-uat/**` or the workflow, or a manual run: builds, pushes and mounts the stack. Every run is idempotent.
- Manual runs accept `allowed_ips` (comma-separated CIDRs) to keep the web app restricted to those addresses; an empty value opens it. Push runs keep whatever restriction the app already has. The CIDRs are applied only after the seed administrator password has been replaced.

## Database migrations

Fineract's schema migrations run in the `genesis-fineract-migrate` job, not in the app. The job has no health probes (up to 90 minutes), so a long first migration on the small database server is never restarted half-way. A restarted migration leaves Liquibase's lock behind and blocks every later start. The app starts with `FINERACT_LIQUIBASE_ENABLED=false` against the migrated schema.

Before each migration the deploy releases any leftover Liquibase lock, but only after confirming that no migration is running. To do this it briefly allows the runner's IP on the database firewall and removes the rule again at the end. A manual run with `reset_fineract_db` drops and recreates the two UAT databases first; the web app is locked to the runner again until the seed password has been replaced.

## Secrets

All passwords are generated by the workflow and held only as Container App secrets; nothing is committed or printed.

- `genesis-fineract-uat` and `genesis-fineract-migrate`: `db-password`, `master-password` (generated once and reused — Fineract stores the tenant connection on first start; kept on both so either can be recreated).
- `genesis-mifos-uat`: `admin-password` for the Fineract user `mifos`. The seed password is replaced while the web app accepts only the runner's IP; the app opens only after the new password signs in.

Read the administrator password (Cloud Shell):

```bash
az containerapp secret show -g genesis-banking-rg -n genesis-mifos-uat --secret-name admin-password --query value -o tsv
```

## Not included
